# pick12 — Draft-Day War Room (Design)

**Date:** 2026-08-26
**Status:** Approved (brainstorming session)

## Purpose

A tablet Expo app for a single user to run their offline (in-person) 2026 fantasy
football draft: 12 teams, full PPR, snake, drafting from slot 12. The app tracks
every pick in the room, recommends picks via a local valuation engine with
needs-weighted Monte Carlo survival odds, and works with zero connectivity on
draft day.

## League parameters (defaults, editable in Settings)

- 12 teams, snake draft, user is slot **12** (turn picks 12/13, 36/37, 60/61, …)
- Full PPR scoring
- Lineup: QB, RB, RB, WR, WR, WR, TE, FLEX (RB/WR/TE), K, DST — 10 starters
- Bench: 5 → **15 rounds, 180 picks**
- No keepers, no pick trades assumed (mis-entered picks fixable on the Board screen)

## Architecture

New standalone repo `C:\Users\chuck\source\repos\pick12`. Single Expo app
(SDK 54, expo-router, TypeScript), tablet-first landscape UI, dark theme.
No backend; all logic and data on-device.

```
pick12/
  app/                       # expo-router screens
  lib/engine/                # pure TS: snake math, projections, VORP, tiers, Monte Carlo
  lib/data/                  # snapshot fetch/merge/validate (shared by app + build script)
  lib/state/                 # zustand store, persisted to AsyncStorage on every pick
  assets/snapshot.json       # bundled rankings snapshot
  tools/refresh-snapshot.ts  # regenerates the bundled snapshot at build time
```

`lib/engine` and `lib/data` are pure TypeScript with no React Native imports so
they run under Node for tests and the build script.

## Data

### Player

Sleeper id, name, position (QB/RB/WR/TE/K/DST), NFL team, bye week, injury
status, ADP, ADP std-dev, overall consensus rank, positional rank, user tag
(`target` / `avoid` / none), user note.

### Snapshot

`{ fetchedAt, players[] }`. Sources, both free and keyless:

- **FantasyFootballCalculator ADP API** — 12-team PPR mode: ADP, ADP std-dev, rank.
- **Sleeper player database** (`/v1/players/nfl`) — team, bye, injury status, ids.

Merge on normalized name + position. Unmatched players are kept with
FFC-only data and surfaced in a post-refresh review list, never silently dropped.
Validation before accepting a snapshot: minimum player count (≥150) and all six
positions present.

### Refresh flow (in-app button + build script share one module)

Fetch → merge → validate → atomic write to app document storage. The stored
snapshot is loaded in preference to the bundled one. On any failure the previous
snapshot is untouched and an error banner is shown. The home screen always shows
"Rankings as of ‹date/time›".

### DraftState

League config + ordered `picks[]` (`{overall, teamSlot, playerId}`). The picks
array is also the undo history (undo = pop). Every pick writes through to
AsyncStorage synchronously; relaunch resumes mid-draft exactly.

## Engine

### Projections

Projected points = baked-in historical PPR scoring curve per position evaluated
at the player's current positional rank (e.g., WR14 ≈ curve value). Curves are
static tables averaged over recent seasons; no network needed and stable enough
for draft ordering.

### VORP

Replacement baselines derived from league config, not hardcoded: 12 teams ×
lineup gives approximately QB13, RB≈30, WR≈44, TE13, with the FLEX share
apportioned by position value. VORP = projection − positional baseline. K/DST
are pinned to the value floor until the final two rounds.

### Tiers

Gap detection on the per-position projection curve → tier bands in the UI, with
cliff alerts ("last 2 RBs in tier 3").

### Monte Carlo survival

Between user turns there are 22 opponent picks. ~500 simulations sample each
opponent pick from an ADP-window candidate pool weighted by that team's actual
unfilled roster slots (tracked on the full board). Outputs:

- per-player survival probability to the user's next pick
- expected best-available per position at the user's next pick

Seeded RNG for reproducibility/testing. Recomputes after every pick; budget
<100 ms on tablet. If roster state is inconsistent, degrades gracefully to
pure-ADP survival.

### Turn-pair recommendation

At the first pick of a back-to-back turn (12, 36, 60, …) the recommendation
evaluates two-player pairs: value of (A now + B at the second pick) vs. taking
one and gambling on survival to the next turn. Output reads like: "Take the WR
now (12% survival) and the RB at 13 (safe) — best pair by +18 points."

At non-pair moments the card ranks options by VORP now + opportunity cost (the
expected value lost at the next turn by not taking this position now). Every
recommendation shows one-sentence reasoning — no black box.

## Screens

- **Setup / resume** — pre-filled league config, optional names for the other 11
  teams, Start button; auto-resumes an in-progress draft.
- **War room (main)** — left pane: best-available list with tier bands, position
  filter chips, search; columns: rank, pos, team, bye, ADP, VORP, survival-% to
  next user pick; target⭐/avoid🚫 tags visible. Right pane swaps between
  recommendation card (pair card at turns), my roster, and on-the-clock team +
  needs. Persistent header: "Pick 3.07 — Team 7 on the clock — 4 picks until
  you" + always-visible Undo.
- **Board** — 12×15 snake grid, color-coded by position; tap a cell to reassign
  or remove a mis-entered pick.
- **Player detail** — tag, note, projection/tier/ADP detail.
- **Settings** — refresh rankings (+ snapshot age), league config, export final
  rosters to clipboard, reset draft (double-confirm).

### Draft-day tap loop

Picks auto-advance in snake order. Logging an opponent's pick: tap player →
confirm sheet (team pre-inferred from order, editable) → confirm. Two taps.

## Mock-draft mode

Practice mode reusing the opponent-pick sampler: the app drafts the other 11
teams, the user rehearses from slot 12. In scope; first cut if time is tight.

## Error handling summary

- Refresh is non-destructive; failures keep the old snapshot + error banner.
- Snapshot validation gates acceptance; merge misses go to a review list.
- Write-through persistence per pick; full resume on relaunch.
- Undo always available (picks array is the history).
- Sim degrades to ADP-only survival on inconsistent state.

## Testing

Engine and data layers are pure TS, tested with `tsx --test` (Node's built-in
runner): snake math (overall ↔ round/slot, user-turn detection), baseline
derivation from config, tier gap detection, seeded-sim determinism, needs
weighting, pair recommendation, and FFC/Sleeper merge against fixture payloads.
UI stays thin over the store. End-to-end verification: a scripted full 15-round
mock draft.

## Out of scope

Keepers, auction formats, pick trades, multi-league support, any backend, live
league-platform integration, analyst point projections, pick timers.
